# Roadmap

## Purpose

This roadmap describes the long-term evolution of **KUKULCAN.SharedKernel.i18n**.

It is intended to communicate the strategic direction of the project rather than provide fixed delivery dates.

The roadmap may evolve as the framework grows.

---

# Vision

The long-term objective of KUKULCAN.SharedKernel.i18n is to become a stable, modern and maintainable architectural foundation for enterprise software based on:

- Domain-Driven Design (DDD)
- Clean Architecture
- CQRS
- Event-Driven Design

The project prioritises architectural quality over rapid feature growth.

---

# Guiding Principles

Future development follows these principles.

- API stability.
- Backward compatibility.
- Simplicity.
- High cohesion.
- Low coupling.
- Framework independence.
- Long-term maintainability.

# Out of Scope

The Shared Kernel intentionally does **not** aim to become:

- An ORM.
- A Dependency Injection container.
- A Logging framework.
- A Web framework.
- A Serialization library.
- A Validation framework replacement.
- A general-purpose utility library.

The project remains focused on architectural building blocks.

---

# Success Criteria

The project will be considered successful if it remains:

- Stable.
- Predictable.
- Easy to understand.
- Easy to maintain.
- Pleasant to use.
- Suitable for long-term enterprise projects.

---

# Release Philosophy

The project follows:

```
Quality > Quantity
```

A smaller, coherent API is preferred over a larger but inconsistent one.

New features will only be added when they improve the architecture.

---

# Community Feedback

Community feedback is one of the main drivers of future evolution.

Suggestions, discussions and improvement proposals are always welcome.

However, every proposal will be evaluated according to the architectural principles described in:

- GOVERNANCE.md
- API_GUIDELINES.md

---

# Final Note

The goal of KUKULCAN.SharedKernel.i18n is not to grow indefinitely.

The goal is to become a stable architectural foundation that developers can confidently depend on for many years.

The best roadmap is one where future versions introduce meaningful improvements while preserving the trust developers place in the framework.
